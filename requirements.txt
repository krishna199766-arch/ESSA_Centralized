# What Vercel installs for the serverless function in api/index.py.
#
# Deliberately NOT the same list as backend/requirements.txt, because the
# platform is not the same:
#
#   uvicorn      — Vercel runs the ASGI app itself; there is no server to start.
#   pytesseract  — needs a `tesseract` binary, which this runtime has not got.
#                  Extraction is vision-only here (see below).
#   pdf2image    — needs poppler, likewise absent. It was never actually called
#                  anywhere; PDFs now go to the model as documents instead.
#
# Dropping tesseract means there is no offline OCR fallback: a deployment with
# no ANTHROPIC_API_KEY cannot read an invoice at all. Everything else — GRN,
# inventory, labels, dispatch, the phone app, the shop — works regardless.
#
# ---------------------------------------------------------------------------
#  Why these four are pinned NEWER than the warehouse PC runs
# ---------------------------------------------------------------------------
#  pillow, rapidfuzz, pydantic-core and psycopg2-binary are the only compiled
#  packages here; everything else is pure Python and installs anywhere.
#
#  The builder selects CPython 3.14 and ignores .python-version, pyproject.toml
#  and Pipfile.lock alike — a known platform bug, not something this repo can
#  configure its way out of. At 3.14 the late-2024 versions of these four have
#  no wheels, so uv compiled all four from source, and psycopg2 got as far as
#  needing the Postgres C headers (`pg_config`) that no build image carries.
#
#  Fighting for an older interpreter was the wrong direction. Every one of the
#  four publishes cp314 wheels at the versions below, so the build downloads
#  them instead of compiling, and stays correct whichever interpreter the
#  platform picks next. .python-version is kept as well: harmless if ignored,
#  and it puts the build back on the tested 3.12 if the bug is fixed.
fastapi==0.115.5
sqlalchemy==2.0.36
pydantic==2.13.4
python-multipart==0.0.19
pillow==12.3.0
rapidfuzz==3.14.5
anthropic==0.40.0
python-barcode==0.15.1
segno==1.6.1

# Reading a master somebody already keeps in a spreadsheet. Categories and
# attribute vocabularies arrive as .xlsx far more often than they arrive typed,
# and the alternative to reading one is a person retyping several hundred rows.
#
# openpyxl only READS here — nothing writes a workbook — and it is pure Python
# with one dependency, so it costs a serverless cold start almost nothing.
# pypdf is for the same job when the list only exists as a PDF; it extracts TEXT,
# which is honest for a printed list and unreliable for a laid-out table (see
# services/master_import.py, which says so to the user rather than guessing).
openpyxl==3.1.5
pypdf==6.16.2

# Postgres. SQLite is a file, and this runtime has nowhere to keep one.
psycopg2-binary==2.9.12
